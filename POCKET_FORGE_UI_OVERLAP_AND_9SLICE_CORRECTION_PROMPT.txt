POCKET FORGE — 메인·장비·박물관·업적·연구 UI 배치 및 9-SLICE 교정 프롬프트
================================================================================

문서 목적
---------

이 문서는 현재 적용된 Pocket Forge UI에서 확인되는 겹침, 잘림, 과밀 배치,
잘못 늘어난 표면과 9-slice 오용을 한 번에 교정하기 위한 실행용 프롬프트다.
다른 Codex/Claude 작업에 이 파일 전체를 입력해도 되도록 작성했다.

이번 목표는 UI를 새로 디자인하는 것이 아니다.
현재 승인된 보랏빛 캐주얼 UI 자산과 기능을 그대로 유지하면서
RectTransform, 앵커, 내부 영역, 렌더 타입과 Sprite Border를 올바르게 교정하는 것이다.

3. 현재 코드에서 확인된 핵심 원인
----------------------------------

다음 사실을 먼저 확인하고 작업하라.

1. CanvasScaler는 1080×1920 기준이며 matchWidthOrHeight=0으로 너비에 맞춘다.
2. 1440×3088 화면은 1080 기준 좌표에서 약 1080×2316의 세로 작업 공간으로 환산된다.
3. Task 13 자산은 MineUiSkin.Task13Simple()을 통해 Sprite Border가 0인 Sprite로 생성된다.
4. Task 13의 모달·카드·버튼은 ApplyStretchedSimpleSprite()로 preserveAspect=false 상태에서 늘어난다.
5. MineUiSkin.Sliced()는 기존 Final 루트에만 있고 Task13 전용 Sliced 생성 경로가 없다.
6. 따라서 Image.type만 Sliced로 바꾸면 정상적인 9-slice가 되지 않는다.
7. Sprite.border가 0이면 Sliced는 보호할 코너와 테두리를 알 수 없다.
8. Border가 있더라도 목표 Rect가 왼쪽+오른쪽 또는 위+아래 Border 합보다 작으면
   코너가 서로 밀리고 중앙이 사라져 UI가 오밀조밀하고 두꺼워진다.
9. 비교 트레이처럼 내부 구분선이 그려진 이미지를 통째로 늘리면
   외곽뿐 아니라 내부 칸까지 늘어나거나 압축된다.

증상을 단순히 좌표 몇 개 옮기는 방식으로 가리지 말고 위 원인을 먼저 교정하라.


4. 절대 보존 조건
-----------------

- 현재 보랏빛 광산 배경과 캐주얼 남색·보라·청록·주황 UI 팔레트를 유지한다.
- 메인 HUD의 현재 기능을 제거하거나 새 기능으로 대체하지 않는다.
- 장비는 4개 장착 슬롯, 2×3 인벤토리, 비교, 해제/장착, 3개 합성, 자동 장착을 유지한다.
- 박물관은 2×2 광물 전시, 발견/미발견, 진행도, 보너스, 다음 보상을 유지한다.
- 업적은 6행, 목표, 진행도, 보상, 수령/진행 중/완료 상태를 유지한다.
- 연구는 3개 노드, 레벨, 보너스, 선행 조건/비용, 구매 상태를 유지한다.
- 한국어·영어·일본어·중국어 동적 텍스트를 유지한다.
- 이미지에 글자나 동적 수치를 새로 굽지 않는다.
- 아이콘의 종횡비와 현재 생성 자산 자체는 가능한 한 유지한다.
- 사용자가 승인한 가스샷의 정보 계층을 유지한다.
- 화면 전체 이미지를 하나의 클릭 불가능한 스프라이트로 교체하지 않는다.

6. 9-SLICE 엔지니어링 계약 — 최우선
====================================

6.1 Image.Type.Sliced만 지정하는 것은 금지
-------------------------------------------

다음 네 조건이 모두 충족된 경우에만 Sliced를 사용한다.

1. Sprite가 0이 아닌 실제 Border를 가진다.
2. Border가 투명 캔버스 끝이 아니라 보이는 외곽 장식의 안쪽을 기준으로 측정됐다.
3. Border 바깥 네 모서리에 늘어나면 안 되는 모든 곡률·광택·테두리가 포함된다.
4. 대상 Rect가 Border 합과 최소 중앙 영역보다 충분히 크다.

이 중 하나라도 충족하지 않으면 Sliced로 설정하지 말고
자산을 다시 트림하거나 Simple 고정 비율 또는 분리 조립을 사용한다.


6.2 Task13 전용 Sliced 경로
---------------------------

MineUiSkin에 Task13Sliced와 동등한 전용 경로를 추가하라.
구현 방식은 프로젝트 스타일에 맞추되 다음 계약을 지켜라.

- 입력: assetName과 원본 텍스처 픽셀 기준 Vector4 borderPixels
- Vector4 순서: left, bottom, right, top임을 코드와 주석에 명시
- Sprite.Create에 실제 pixel border를 전달
- 캐시 키에 assetName과 네 Border 값을 모두 포함
- SpriteMeshType.FullRect 유지
- Border 값은 0 이상이며 각 축 합이 텍스처 크기보다 작아야 함
- 잘못된 Border는 조용히 통과시키지 말고 Debug.Assert 또는 명확한 경고를 남김
- 모든 Task13 자산에 같은 Border를 적용하지 않음

예시 의도:

Task13Sliced("UiEquipmentModalBody", measuredBorderPixels)
Task13Sliced("UiEquipmentInventoryCardBase", measuredBorderPixels)
Task13Sliced("ButtonEquipmentEquip", measuredBorderPixels)

숫자는 예시로 추측하지 말고 실제 PNG의 불투명 경계와 코너 장식을 원본 해상도에서 측정하라.


6.3 Sliced 적용 헬퍼 계약
-------------------------

Sliced 표면에 사용하는 공용 헬퍼는 다음을 보장해야 한다.

- image.sprite = 실제 Border가 포함된 Sprite
- image.type = Image.Type.Sliced
- image.preserveAspect = false
- image.fillCenter = true
- image.color = Color.white 또는 의도된 tint
- pixelsPerUnitMultiplier를 화면마다 임의로 바꾸지 않음
- SetNativeSize()를 호출한 뒤 다시 강제 stretch하지 않음
- 동일 Prefab/계열은 같은 Border와 같은 pixelsPerUnitMultiplier 사용

기존 ApplyStretchedSimpleSprite()를 이름만 바꿔 사용하지 마라.
실제 sprite.border가 0이 아닌지 적용 직후 확인하라.


6.4 Border 측정 절차
--------------------

자산마다 아래 순서로 측정한다.

1. 원본 PNG를 실제 해상도로 연다.
2. 완전 투명 행/열을 제거하거나 실제 보이는 자산 영역을 Sprite rect로 사용한다.
3. 좌우상하에서 코너 곡률, 테두리, 하이라이트와 그림자가 끝나는 지점을 찾는다.
4. 그 지점보다 1~2px 안쪽을 stretchable center 시작점으로 잡는다.
5. Border 밖 중앙 행/열이 거의 균일한 색·그라데이션인지 확인한다.
6. 내부 아이콘, 분리선, 특수 하이라이트가 중앙 stretch 영역을 가로지르면 Sliced 후보에서 제외한다.
7. source preview에서 초록색 Border 선을 확인한다.
8. 최소/기준/최대 Rect 세 크기로 렌더해 코너 두께를 비교한다.

투명 여백을 Border에 포함하면 실제 테두리가 보호되지 않고 중앙이 과도하게 줄어든다.
먼저 알파 트림 또는 올바른 Sprite rect를 사용하라.


6.5 최소 크기 공식
-------------------

모든 Sliced 이미지에 아래 조건을 적용한다.

targetWidth >= leftBorder + rightBorder + minimumCenterWidth
targetHeight >= topBorder + bottomBorder + minimumCenterHeight

minimumCenterWidth와 minimumCenterHeight는 최소 8px,
광택 그라데이션이 있는 자산은 16px 이상으로 둔다.

이 조건을 만족하지 못하면 다음 중 하나를 선택한다.

- Rect를 키운다.
- 더 작은 Border를 실제 이미지에서 다시 측정한다.
- 동일 종횡비의 Simple 고정 크기로 사용한다.
- 표면과 장식을 여러 자산으로 분리한다.

Border를 억지로 작게 만들어 코너 일부가 늘어나게 하지 않는다.

6.7 비교 트레이 교정
--------------------

현재 장비 비교 트레이는 내부 세로 칸과 외곽이 함께 압축되어 잘게 쪼개져 보인다.
다음 구조로 다시 조립하라.

EquipmentCompareRoot
├─ Background: 균일한 빈 표면만 가진 Sliced 이미지
├─ LeftZone: 투명 RectTransform
├─ CenterIndicatorZone: 고정 폭 투명 RectTransform
├─ RightZone: 투명 RectTransform
├─ DividerLeft: 2~4px Simple 이미지 또는 코드 색상 선
├─ DividerRight: 2~4px Simple 이미지 또는 코드 색상 선
└─ RuntimeTextAndIcons

- 원래 구분선이 그려진 전체 트레이 이미지를 Sliced하지 않는다.
- 좌우 영역의 너비를 같게 유지한다.
- 중앙 표시 영역은 텍스트 최대 폭을 기준으로 고정한다.
- 구분선은 외곽 테두리와 최소 12px 떨어뜨린다.
- 비교 텍스트와 구분선이 겹치지 않아야 한다.


7. 메인 화면 교정
=================

7.1 현재 실패
-------------

- 상단 프로필·XP·재화 모듈이 너무 작고 값과 아이콘이 서로 압박한다.
- 상단 자원 바의 각 모듈 경계가 흐려져 하나의 긴 압축 바처럼 보인다.
- 보스 준비/도전 버튼이 우측 연구 카드와 수직으로 가까워 소유 관계가 모호하다.
- 강화 카드 하단 가격과 강화 화살표가 카드 경계에 붙거나 밖으로 돌출된다.
- 하단 내비게이션의 첫 번째와 마지막 셀이 Safe Area 끝에 붙고 일부 장식이 잘린다.
- 하단 내비게이션 아이콘·라벨의 기준선이 흔들리고 중앙 선택 장식이 다른 셀보다 튀어나온다.


7.2 교정 계약
-------------

[상단 HUD]
- 프로필과 XP는 하나의 그룹이지만 프로필 불투명 영역이 XP 텍스트 영역을 침범하지 않게 한다.
- Credits, Gem, Core는 각각 독립된 아이콘 영역·값 영역·추가 버튼 영역을 가진다.
- 자원 모듈 사이 최소 간격 12, 내부 좌우 패딩 최소 14.
- 숫자 영역은 최소 5자리 축약 표기와 아이콘을 동시에 수용해야 한다.
- 설정 버튼은 상단 바 외부 우측 독립 영역에 두고 마지막 자원 모듈과 최소 18 간격을 둔다.

[챕터와 전투력]
- 챕터 카드와 전투력 카드는 상단·하단·테두리 곡률을 맞춘다.
- 두 카드 사이 최소 24 간격.
- 전투력 값과 권장치 문구의 텍스트 Rect가 겹치지 않는다.

[보스]
- 보스 준비 배지는 중앙 광석 위의 독립 행이다.
- 보스 도전 버튼은 우측 연구 카드와 겹치지 않는 전용 행에 둔다.
- 보스 버튼이 연구 카드의 자식처럼 보이지 않도록 수직 간격 24 이상 확보한다.

[채굴 행동]
- 오프라인 보상, 채굴 버튼, 연구 바로가기는 같은 높이의 3열로 정렬한다.
- 좌우 보조 카드와 중앙 채굴 버튼 사이 각각 최소 24 간격.
- 보스 도전 버튼은 이 3열 위 또는 아래의 별도 행이며 절대 연구 카드 위에 떠 있지 않는다.

[강화 카드]
- 곡괭이·드릴·로봇 카드의 Rect는 완전히 같은 너비·높이여야 한다.
- 세 카드 중심 x와 간격을 고정한다.
- 카드 내부는 이름 | 아이콘 | 레벨 | 가격+화살표 영역으로 분리한다.
- 가격 아이콘·가격 값·강화 화살표 모두 카드 안쪽 20px 안전선 안에 둔다.
- 추천 배지는 카드 우상단 안쪽에 두고 외곽 밖으로 나가지 않게 한다.

[하단 내비게이션]
- 전체 바를 Safe Area 좌우 54 안에 완전히 넣는다.
- 6개 셀의 너비와 중심 간격을 동일하게 한다.
- 첫 셀과 마지막 셀의 불투명 아이콘 경계가 바깥으로 나가지 않아야 한다.
- 선택 탭 장식은 셀 Rect 안에서만 커지며 인접 셀을 침범하지 않는다.
- 아이콘 중심선과 라벨 기준선을 모든 셀에서 동일하게 한다.


8. 장비 화면 교정

8.1 현재 실패

- 타이틀 플라크, 좌상단 보유량 캡슐, 우상단 닫기 버튼이 같은 높이에 몰려 있다.
- 타이틀 플라크 우측 테두리와 닫기 버튼이 겹친다.
- 보유량 캡슐이 헤더 장식과 연결되지 않은 채 떠 있다.
- 4개 장착 슬롯과 3열 인벤토리는 구분은 되지만 세로 간격이 부족하다.
- 장비 카드 하단 수량 배지가 외곽 테두리에 붙어 있다.
- 비교 트레이가 3개의 작은 프레임처럼 압축됐다.
- 행동 버튼 3개와 닫기 버튼이 모달 하단을 과도하게 점유하고 일부가 바닥에 붙는다.


8.2 모달 지역 계약
------------------

920×1400 로컬 모달을 아래 영역으로 분할한다.

- Header: 상단 0~150
- SummaryAndCapacity: 150~230
- EquippedSlots: 230~470
- InventoryGrid: 490~1020
- Pagination: 1036~1100
- Comparison: 1118~1238

인접 영역은 절대 교차하지 않는다.


8.3 헤더
--------

- 타이틀 플라크 폭 최대 620, 높이 120~126.
- 닫기 버튼 84×84, 우상단 안쪽 28.
- 타이틀과 닫기 버튼의 외곽 사이 최소 20.
- 보유량 캡슐은 타이틀 행에서 제거하고 SummaryAndCapacity 행의 좌측에 둔다.
- 채굴력 요약은 같은 행 중앙 또는 우측에 배치한다.
- 보유량과 요약 텍스트 영역이 겹치지 않는다.


8.4 4개 장착 슬롯
-----------------

- 네 카드의 크기, y, 상단과 하단 기준선을 동일하게 한다.
- 카드 사이 최소 16, 양 끝 내부 여백 최소 32.
- 슬롯 아이콘은 카드 상단 60% 내부에 PreserveAspect로 배치한다.
- 이름·희귀도·보너스는 하단 40%에 최대 2줄로 제한한다.
- 텍스트가 아이콘의 불투명 경계 위에 올라가지 않는다.


8.5 2×3 인벤토리
----------------

- 3열×2행을 유지한다.
- 6개 카드의 너비·높이·간격을 완전히 동일하게 한다.
- 카드 내부 순서: 아이콘 → 이름 → 희귀도/보너스 → 수량 배지.
- 우상단 장착 배지와 합성 배지를 같은 위치에 동시에 표시하지 않는다.
- 합성 배지는 장착 배지 아래 별도 슬롯을 사용한다.
- 수량 배지는 우하단 테두리에서 최소 10px 안쪽에 둔다.
- 선택 테두리는 카드 외곽과 같은 Rect를 사용하고 별도 크기 변경을 하지 않는다.


8.6 비교와 행동
---------------

- 비교 트레이는 6.7의 분리 구조로 다시 만든다.
- 비교 텍스트는 한 줄을 우선하고 최장 언어에서만 두 줄을 허용한다.
- 행동 버튼 3개는 같은 너비·높이·y축을 사용한다.
- 버튼 사이 최소 18.
- 하단의 별도 닫기 버튼은 제거하지 않되 행동 버튼 행과 20 이상 간격을 둔다.
- 공간이 부족하면 닫기 버튼을 3개 행동 버튼 아래 한 행으로 두고 모달 높이를 늘리거나
  콘텐츠 영역을 ScrollRect로 전환한다. 음수 간격이나 겹침으로 맞추지 않는다.


9. 박물관 화면 교정

9.2 교정 계약

- 두 탭은 완전히 같은 크기이며 한 기준선에 둔다.

- 요약 카드의 아이콘 영역은 고정 폭, 텍스트 영역은 나머지 폭을 사용한다.

[다음 보상]

- 오른쪽 75%는 발견 수치와 다음 목표.
- 아이콘과 텍스트 사이 최소 20.
- 스트립 자체는 Simple 고정 비율 또는 균일 배경 Sliced로 사용한다.

10. 업적 화면 교정
==================

10.1 현재 실패
--------------

- 일부 업적 아이콘이 제목 영역까지 넘어와 첫 글자를 가린다.
- 보상 아이콘 옆 수치가 수령 버튼 뒤로 들어간다.
- 행마다 진행 트랙과 보상 열의 시작점이 흔들린다.
- 진행 중 버튼과 수령 버튼의 폭·테두리 인상이 다르다.
- 행 높이에 비해 아이콘과 버튼이 커서 중앙 텍스트가 눌린다.
- 타이틀과 닫기 버튼도 동일하게 겹친다.


10.2 5열 고정 계약
------------------

업적 행 내부를 다음과 같이 고정한다.

| 열 | 행 너비 비율 | 역할 |
|---|---:|---|
| Icon | 14% | 프레임과 카테고리 아이콘 |
| Objective | 39% | 제목과 진행 수치/트랙 |
| RewardIcon | 11% | 재화 슬롯 |
| RewardValue | 12% | 보상 수량 |
| StateAction | 24% | 수령/진행 중/완료 |

실제 폭 계산 시 열 사이에 최소 8~12px 간격을 먼저 빼고 남은 폭에 비율을 적용한다.

- 모든 행은 같은 열 시작 x와 같은 열 폭을 사용한다.
- 아이콘 불투명 경계는 Icon 열 안에 12px 이상 패딩을 남긴다.
- 제목은 Objective 열 밖으로 나갈 수 없다.
- 진행 수치와 트랙은 Objective 열 내부에서 위아래로 분리한다.
- 보상 수치는 RewardValue 열에서 우측 또는 중앙 정렬한다.
- 수령 버튼은 StateAction 열 안에서만 존재한다.
- 완료 배지도 StateAction 열 중앙을 사용한다.
- 보상 수치와 수령 버튼은 어떤 언어와 값에서도 교차할 수 없다.


10.3 행 높이와 상태
-------------------

- 6개 행의 높이를 동일하게 한다.
- 아이콘 높이는 행 높이의 66% 이하.
- 상태 버튼 높이는 행 높이의 62% 이하.
- 행 사이 최소 16.
- 수령 가능: 주황색 버튼 + 명확한 런타임 라벨.
- 진행 중: 남색/보라색 비활성 캡슐 + 진행 중 라벨.
- 완료: 초록 체크 배지 + 완료 런타임 라벨 또는 접근 가능한 상태 값.
- 색상만으로 상태를 구분하지 않는다.


11. 연구 화면 교정
==================

11.1 현재 실패
--------------

- 연구 모달이 다른 Task13 모달보다 지나치게 작아 UI 체계가 끊긴다.
- 타이틀 플라크가 본체보다 넓어 보이고 외곽과 연결이 어색하다.
- 상단 채굴력 요약과 코어 수치가 서로 가까워 작은 글씨로 축소된다.
- 연구 행 높이가 부족해 이름·레벨·효과가 겹치거나 매우 작아진다.
- 구매 버튼이 눌린 갈색 표면처럼 보이며 주황색 공용 버튼과 일관되지 않는다.


11.2 교정 계약
-------------

- 연구 모달 폭을 장비·수집 모달과 같은 920 계열로 통일하거나,
  최소 760 이상으로 키워 3개 행의 정보를 읽을 수 있게 한다.
- 공용 타이틀/닫기 헤더 구조를 사용한다.
- 헤더 아래에 채굴력 요약 행과 설계도 코어 행을 분리한다.
- 두 값은 최소 20 간격을 두고 같은 Text Rect에 넣지 않는다.
- 연구 행은 최소 높이 150.
- 행 사이 최소 18.

[연구 행 내부]
- 왼쪽 62%: 연구 이름, 레벨, 효과를 세 줄 이하로 배치.
- 오른쪽 30%: 구매/선행 조건/최대 레벨 상태 버튼.
- 가운데 최소 8% 또는 20px 이상의 분리 간격.
- 텍스트는 버튼 뒤로 들어갈 수 없다.
- 버튼 높이는 행 높이의 54~62%.
- 활성 구매 버튼은 공용 주황색 표면을 사용한다.
- 선행 조건 부족/잠금/최대 레벨은 같은 크기의 비활성 남색 표면을 사용한다.
- 버튼 표면은 올바른 Border를 가진 Sliced 또는 동일 종횡비 Simple로 사용한다.


12. 텍스트 계약
===============

- 자동 크기 축소만으로 겹침을 숨기지 않는다.
- 먼저 열 폭과 영역을 확보한 뒤 제한적으로 resizeTextForBestFit을 사용한다.
- 최저 글자 크기가 기본 크기의 70% 아래로 내려가지 않게 한다.
- 제목은 한 줄.
- 카드 이름은 최대 2줄.
- 설명과 보너스는 각각 독립 Rect를 사용한다.
- 숫자는 K/M/B/T/Qa/Qi 축약을 유지한다.
- 보상 수치와 화폐 아이콘은 같은 열을 공유하지 않는다.
- 한국어뿐 아니라 영어·일본어·중국어 최장 문자열을 실제 렌더한다.
- 잘린 글자, 생략 부호 남발, 버튼 밖 글자, 아이콘 위 글자를 허용하지 않는다.


13. 구현 순서
=============

1. 현재 화면을 1440×3088에서 다시 캡처하고 기준선 오버레이를 저장한다.
2. Task13 PNG의 원본 크기, 알파 경계, 실제 장식 경계를 조사한다.
3. 자산별로 Simple / Sliced / Filled / 분리 조립 분류표를 코드 상수 또는 문서로 고정한다.
4. MineUiSkin에 실제 Border를 가진 Task13Sliced 경로를 추가한다.
5. Sliced 적용 헬퍼와 잘못된 최소 크기 방어를 추가한다.
6. 비교 트레이와 내부 구획형 표면을 분리 조립한다.
7. 공용 모달 헤더부터 교정해 장비·박물관·업적의 타이틀/닫기 충돌을 한 번에 해결한다.
8. 장비, 박물관, 업적, 연구 순서로 내부 레이아웃을 교정한다.
9. 마지막에 메인 HUD와 하단 내비게이션을 교정한다.
10. 각 단계마다 다른 화면의 자산 타입과 좌표가 바뀌지 않았는지 회귀 검사한다.


14. 자동 회귀 테스트 요구
=========================

기존 테스트에 아래 검사를 추가하거나 동등한 검증을 구현하라.

[Sprite/9-slice]
- Sliced로 분류된 모든 Sprite의 border 네 값 중 필요한 축이 0이 아님
- left+right+minimumCenterWidth <= source width
- top+bottom+minimumCenterHeight <= source height
- target Rect가 Border 합과 최소 중앙 크기 이상
- 아이콘·배지·Filled 자산이 Sliced로 설정되지 않음
- 진행 Fill은 Filled 또는 기존 폭 기반 방식 중 의도한 하나만 사용
- 분리 조립 대상 원본 전체 이미지가 Sliced로 사용되지 않음

[반복 요소]
- 장비 장착 슬롯 4개 동일 Rect
- 장비 인벤토리 6개 동일 Rect와 동일 행/열 간격
- 박물관 4개 카드 동일 Rect
- 업적 6행 동일 Rect
- 업적 Icon/Objective/Reward/State 열의 x좌표 동일
- 연구 3행 동일 Rect와 동일 버튼 열

[교차 금지]
- 모든 모달 TitleSurface ↔ CornerCloseButton 비교차
- EquipmentCapacity ↔ EquipmentTitle 비비교차
- EquipmentCompareText ↔ Divider 비비교차
- AchievementIcon ↔ AchievementName 비비교차
- AchievementReward ↔ ClaimButton 비비교차
- MuseumLockedOverlay ↔ Name/Details/Bonus 비비교차
- ResearchTextZone ↔ PurchaseButton 비비교차
- UpgradeArrow ↔ UpgradeCard exterior 비비교차
- BottomNavigation first/last cell이 Safe Area 내부

[화면비]
- 16:9
- 19.5:9
- 20:9
- 1440×3088 중앙 펀치홀 프로필

각 화면비에서 Safe Area를 적용한 뒤 검사하며 이전 프레임의 stale safeArea 값도 방어한다.


15. 시각 검수 요구
=================

반드시 다음 캡처를 남긴다.

- 메인 1440×3088
- 장비 1440×3088
- 박물관 1440×3088
- 업적 1440×3088
- 연구 1440×3088
- 16:9 메인과 모달 1종
- 19.5:9 메인과 모달 1종
- 20:9 메인과 모달 1종

각 캡처에서 다음을 확인한다.

1. 가스샷과 같은 해상도로 맞춰 50% 오버레이한다.
2. 모달 중심축, 제목, 카드 열, 하단 버튼 기준선을 비교한다.
3. Sliced 자산을 최소/현재/최대 Rect로 나란히 렌더한다.
4. 세 크기에서 모서리 반지름과 테두리 굵기가 같아야 한다.
5. 중앙 면만 늘어나고 코너 장식·광택·그림자가 늘어나지 않아야 한다.
6. 이전보다 더 오밀조밀해졌다면 Border 또는 최소 Rect가 잘못된 것이므로 승인하지 않는다.
7. Simple 자산은 원본 종횡비와 실제 표시 종횡비 차이가 3%를 넘지 않아야 한다.
8. 아이콘은 PreserveAspect 상태에서 불투명 경계 기준으로 카드 안에 들어가야 한다.


16. 절대 금지
=============

- 모든 Image를 일괄 Sliced로 바꾸기
- Sprite Border가 0인데 Image.Type.Sliced만 지정하기
- 모든 자산에 동일한 normalizedBorder 사용하기
- 투명 여백을 포함한 전체 PNG 크기만 보고 Border 정하기
- 목표 Rect가 Border 합보다 작은 상태로 강제 렌더하기
- 내부 칸·아이콘·구분선이 포함된 이미지를 통째로 Sliced하기
- 겹침을 해결하기 위해 글자만 극단적으로 줄이기
- 음수 간격과 카드 밖 anchoredPosition으로 억지 배치하기
- Auto Size만 켜고 최장 다국어 문자열을 검증하지 않기
- 아이콘 종횡비를 끄고 카드 크기에 맞춰 늘리기
- 장비·박물관·업적 기능이나 데이터 구조 변경하기
- 현재 승인된 UI 자산을 임의의 코드 색상 사각형으로 대체하기
- 한 화면 수정 중 다른 화면의 공용 좌표를 무단 변경하기
- 테스트하지 않은 화면비를 완료로 보고하기


17. 완료 조건
=============

다음 조건을 모두 만족해야 작업 완료로 보고한다.

- 5개 화면의 명시된 겹침과 잘림이 모두 사라짐

- 최소/기준/최대 크기에서 9-slice 코너와 테두리가 동일함
- 16:9, 19.5:9, 20:9 회귀 검사를 통과함
- 한국어·영어·일본어·중국어 최장 문자열 검사를 통과함
