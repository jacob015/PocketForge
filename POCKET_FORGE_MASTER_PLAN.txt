1. 게임 한 줄 소개
------------------

Pocket Forge는 세로 화면에서 광석을 채굴하고 자동화 시설과 영구 성장 요소를 강화해 챕터 보스를 돌파하는 3D 캐주얼 방치형 모바일 게임이다.

초반에는 직접 탭하는 재미가 강하지만, 챕터가 진행될수록 자동 채굴과 광부 등급, 연구, 장비, 수집 등 전체 스펙을 성장시키지 않으면 보스를 돌파할 수 없도록 설계한다.


2. 제품 방향
------------

2.1 장르

- 기존 클릭커 중심 구조에서 하이브리드 방치형 구조로 전환한다.
- 자동 생산과 오프라인 보상이 진행의 본체다.
- 탭은 초반 진행, 능동 가속, 보스 개입 수단으로 유지한다.
- 단순히 숫자만 커지는 게임이 아니라 여러 성장축을 열고 투자 대상을 선택하는 구조를 만든다.

2.2 시각 방향

- Supercent 계열 캐주얼 모바일 게임처럼 즉시 이해되는 밝고 선명한 화면을 목표로 한다.
- 레퍼런스를 그대로 복제하지 않고 Pocket Forge의 광산·크리스털 테마로 재설계한다.
- 큰 버튼, 강한 아이콘 실루엣, 읽기 쉬운 재화와 진행도, 짧고 명확한 긍정 피드백을 사용한다.
- UI와 모델은 실제 게임 화면 전체 스냅샷을 먼저 만든 뒤 부품을 분해·적용한다.
- 그래픽 리소스는 모바일 성능과 빌드 용량을 우선한다.

2.3 플랫폼

- Android 우선
- Portrait 고정
- Safe Area와 16:9, 19.5:9, 20:9 계열 화면비 대응
- Google Play 비공개 테스트를 거쳐 출시 가능한 구조를 목표로 한다.


3. 핵심 게임 루프
-----------------

1) 자동 장비가 현재 일반 스테이지의 광석을 지속해서 채굴한다.
2) 플레이어는 탭으로 채굴 속도를 보조한다.
3) 광석에서 Credits와 광부 XP를 획득한다.
4) Credits로 곡괭이, 드릴, 로봇 시설을 강화한다.
5) 광부 등급, 연구, 장비, 도감 등 영구 성장 요소를 누적한다.
6) 챕터 마지막 스테이지의 보스 권장 채굴력을 확인한다.
7) 제한 시간 안에 보스를 처치하면 다음 챕터와 보상을 획득한다.
8) 실패하면 직전 일반 스테이지에서 자동 파밍한 뒤 명시적으로 재도전한다.
9) 접속하지 않은 시간에도 마지막으로 도달한 일반 스테이지를 기준으로 보상을 누적한다.
10) 미션, 수집, 이벤트, 상점이 다음 플레이 목표를 제공한다.


4. 채굴과 전투 규칙
-------------------

4.1 자동 채굴 [완료]

- 기본 자동 채굴력: 0.5/s
- 드릴 레벨이 자동 출력의 기본값을 높인다.
- 로봇 레벨이 자동 출력에 배율로 기여한다.
- 자동 채굴은 탭하지 않아도 일반 광석의 체력을 감소시킨다.

4.2 탭 채굴 [완료]

- 곡괭이 레벨이 기본 탭 피해를 높인다.
- 탭 피해는 광부 등급과 연구 같은 전체 성장 배율의 영향을 받는다.
- 0.2초 입력 쿨다운으로 초당 최대 5회만 유효하다.
- 후반에도 탭이 완전히 무의미해지지 않도록 자동 채굴력 일부를 탭 피해의 하한으로 사용한다.

4.3 총 채굴력 [부분 완료]

현재 공식:

시설 기본 출력
× 광부 등급 배율
× 장비 배율
× 연구 배율
× 광물 도감 배율
× 일시 버프 배율

현재 실제 적용:

- 시설: 적용
- 광부 등급: 적용
- 연구: 적용
- 장비: 적용
- 광물 도감: 확장 지점만 존재
- 일시 버프: 확장 지점만 존재

총 채굴력은 저장하지 않고 현재 저장 데이터와 콘텐츠 정의에서 매번 계산한다.


5. 챕터와 보스
--------------

5.1 기본 구조 [완료]

- 한 챕터는 10개 스테이지로 구성한다.
- 각 챕터의 10번째 스테이지는 보스다.
- 보스 제한 시간은 현재 30초다.
- 보스 권장 채굴력은 보스 내구도 ÷ 제한 시간으로 계산한다.
- 보스 실패 시 보상 없이 직전 일반 스테이지로 이동한다.
- 이미 도달한 보스는 일반 스테이지 파밍 중 자동으로 재진입하지 않는다.
- 플레이어가 챕터 상태 버튼에서 도전을 선택해야 재도전한다.

5.2 현재 챕터 데이터 [완료, 초기 밸런스]

챕터 1: Crystal Cavern
- 스테이지 1~10
- 최초 보상: 100 Credits, 5 Gems, 설계도 코어 3
- 반복 보스 코어: 1
- 보스 내구도 ×3
- 보스 보상 ×5

챕터 2: Magma Depths
- 스테이지 11~20
- 최초 보상: 250 Credits, 10 Gems, 설계도 코어 6
- 반복 보스 코어: 2
- 보스 내구도 ×3.5
- 보스 보상 ×6

챕터 3: Ancient City
- 스테이지 21~30
- 최초 보상: 500 Credits, 15 Gems, 설계도 코어 9
- 반복 보스 코어: 3
- 보스 내구도 ×4
- 보스 보상 ×7

현재 챕터 이름과 수치는 구조 검증용 초기값이며 Task 14에서 다시 밸런싱한다.

5.3 남은 챕터 작업 [예정]

- 챕터별 전용 배경
- 챕터별 보스 모델과 연출
- 챕터별 광석 조합 차별화
- 더 많은 챕터와 스테이지
- 챕터 클리어 연출 강화
- 챕터 보상 테이블 최종화


6. 재화와 숫자 표기
-------------------

6.1 Credits [완료]

- 시설 강화의 기본 재화
- 광석, 오프라인 보상, 광고 보상, 레벨업 보상에서 획득
- 저장 타입은 64비트 정수

6.2 Gem [부분 완료]

- 챕터 최초 클리어와 광부 마일스톤에서 획득
- 향후 편의, 상점, 선택적 가속에 사용
- 저장과 획득은 구현됐지만 실제 소비처는 아직 부족함

6.3 설계도 코어 [완료]

- 보스 최초·반복 처치에서 획득
- 영구 연구 노드 구매에 사용

6.4 향후 재화 원칙

- 소비처가 없는 재화는 먼저 추가하지 않는다.
- 장비 재료는 장비 시스템 구현 단계에서만 추가한다.
- 이벤트 토큰은 실제 이벤트가 구현될 때만 추가한다.

6.5 공통 숫자 표기 [완료]

증가 가능한 모든 플레이어 표시 수치는 같은 단위를 사용한다.

- 1,000 = 1K
- 1,000,000 = 1M
- 1,000,000,000 = 1B
- 1,000,000,000,000 = 1T
- 이후 Qa, Qi 지원

Credits, Gem, 코어, 보상, 비용, XP, 채굴력에 적용한다.

레벨, 챕터, 스테이지, 시간, 진행 개수처럼 식별 의미가 있는 숫자는 축약하지 않는다.

15. 현재 기술 아키텍처
----------------------

15.1 주요 경계

- MineGameController: Unity 생명주기와 의존성 조립
- MiningGameService: 채굴, 보상, 강화, 챕터, 보스, 오프라인 규칙
- MiningPowerService: 자동, 탭, 능동 채굴력과 성장 배율 계산
- MinerProgressionService: XP, 레벨, 보상, 기능 해금
- ResearchService: 연구 구매와 배율
- MiningContentCatalog: 광석, 강화, 챕터, 연구 데이터
- MineHudPresenter: 게임 결과를 UI와 저장 요청에 연결
- MineHudView: 런타임 UGUI와 입력
- SaveService / GameSaveMigrator: 저장과 버전 호환
- MineAdCoordinator: 광고 SDK 경계
- MineIapCoordinator: 결제 SDK 경계

15.2 설계 원칙

- 게임 규칙은 광고·결제 SDK를 직접 참조하지 않는다.
- 콘텐츠 수치는 ScriptableObject 또는 직렬화 데이터로 조절한다.
- 총 채굴력 같은 파생값은 저장하지 않는다.
- 저장에는 원본 성장 데이터만 기록한다.
- 외부 SDK는 인터페이스와 Coordinator를 통해 연결한다.
- 핵심 규칙은 EditMode 테스트에서 독립 검증한다.
- 작은 프로젝트지만 장비·수집·버프를 같은 계산 경계에 연결할 수 있게 한다.

17. 최적화와 용량
-----------------

17.1 현재까지 확인

- 초기 3D 원본을 그대로 포함한 개발 빌드는 약 1GB까지 증가한 적이 있음
- 모바일 메시·텍스처 최적화 후 Task 12 실기기 APK는 약 47~50MiB 수준 확인
- IAP 포함 서명 AAB는 약 48.6MB 수준 확인
- 이후 Task 13 콘텐츠가 포함된 최신 Android 산출물 용량은 아직 다시 측정하지 않음

17.2 최종 목표

- 다운로드·설치 용량을 가능한 한 50MB 전후로 유지
- 불필요한 원본 GLB와 중복 텍스처를 런타임 빌드에서 제외
- 텍스처 최대 크기와 ASTC 압축 유지
- 모바일 메시 폴리곤 수 제한
- 오브젝트 풀링 사용
- 런타임 반복 탐색 최소화
- 저사양 기기의 프레임, 메모리, 발열 확인

17.3 최종 최적화 체크

- APK/AAB 크기
- 텍스처 메모리
- 메시 메모리
- 로딩 시간
- 평균·최저 FPS
- 장시간 발열
- 배터리 소비
- 광고·결제 SDK 초기화 시간

24. 프로젝트 작업 원칙
----------------------

- 구현 전 TASKS.md의 현재 작업과 범위를 확인한다.
- 파일 수정 전 작업 계획과 영향 범위를 사용자에게 알린다.
- 사용자가 승인한 범위만 수정한다.
- 기존 HUD 좌표처럼 사용자가 직접 확정한 값은 별도 승인 없이 변경하지 않는다.
- 외부 SDK, 패키지, Unity 설정, 배포·계정 변경은 사전 승인을 받는다.
- 테스트하지 않은 내용을 완료로 기록하지 않는다.
- 구현 사실은 ARCHITECTURE.md에 기록한다.
- 작업 이력과 검증은 WORKING_CONTEXT.md에 누적한다.
- AI 산출물과 실제 검증을 AI_USAGE.md에 구분한다.
- 작업 완료 후 검증된 변경만 Git에 커밋·푸시한다.


25. 현재 결론
-------------

Pocket Forge는 현재 단순 클릭커 프로토타입을 넘어 다음 기반을 갖췄다.

- 자동·탭·오프라인을 공유하는 채굴력 계산
- 챕터와 제한 시간 보스
- 실패 후 파밍과 재도전
- 광부 레벨과 기능 해금
- 보스 재화와 영구 연구
- 광고와 실제 인앱 결제
- 4개 언어와 모바일 HUD
- 확장 가능한 저장·콘텐츠·SDK 경계

다음 핵심은 장비, 수집·미션, 상점·이벤트를 추가해 플레이 목표와 보상 계층을 충분히 만드는 것이다. 그 뒤 밸런싱과 최종 폴리싱을 통해 프로토타입 느낌을 제거하고, 최적화·비공개 테스트·출시 준비 순서로 진행한다.
